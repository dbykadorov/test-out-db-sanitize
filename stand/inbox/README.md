# Входящие дампы

Положите сюда файл дампа и объявите его в `../config/catalog.json`:

```json
{ "id": "мой-дамп", "kind": "dump", "title": "Дамп заказчика",
  "schemas": ["public"], "path": "/var/lib/sanitize/inbox/мой-файл.dump" }
```

Каталог перечитывается воркером раз в пятнадцать секунд - перезапуск
не нужен. Затем зарегистрируйте имя в контуре управления:

```bash
curl -X POST http://127.0.0.1:8080/api/sources \
  -H 'Content-Type: application/json' -H 'X-Subject: operator@outtech.example' \
  -d '{"id":"мой-дамп","title":"Дамп заказчика","kind":"dump"}'
```

Поддерживаются собственный формат PostgreSQL (`pg_dump -Fc`, каталог `-Fd`)
и обычный текстовый `.sql`. Формат определяется по содержимому файла,
а не по расширению.

Дамп разворачивается в промежуточную базу - это часть рабочей зоны:
там лежат исходные персональные данные, и её содержимое стирается перед
каждой загрузкой.
